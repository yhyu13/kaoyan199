# 习题知识库 · 字段规范（schema v2：双链 + 专栏）

> 这是给**别的 Agent**看的契约。你按这个格式产出，我们这边一条命令入库。
> v1 的条目照样能读——v2 只是在上面加了 `column` / `aliases` 和 `[[双链]]` 解析。

## 1. 存储形态

| 文件 | 作用 | 谁写 |
|---|---|---|
| `知识库/entries.jsonl` | **唯一真相**，一行一条 JSON，只追加不改写 | `_data/kb.py` |
| `知识库/columns.json` | 专栏定义（名字、色调、说明、「怎么收录」） | 手写 |
| `知识库/index.json` | 自动生成的索引 + 图谱模型（节点 / 边 / 断链 / 反链） | 自动 |
| `知识库/index.html` | 自包含浏览页（数据 + KaTeX 全内联，断网可读） | 自动 |

节点空间是**统一**的，图谱里同时有：

| 节点 | id 形如 | 来源 | 点开的去处 |
|---|---|---|---|
| 手记（本库条目） | `kb:<条目id>` | `entries.jsonl` | 知识库详情抽屉 |
| 考点 | `kp:<考点id>` | `_data/knowledge.json`（44 个） | `课.html#kp-<id>` |
| 真题 | `q:<题号>` | `_data/2026管综.json`（55 道） | `真题刷题系统.html#q<题号>` |
| 母题 | `m:<T编号>` | 考点库的题目映射（60 道） | 无独立页 |

考点和真题**不复制**进来，只在构建期读一次。改 `knowledge.json` 后跑 `kb.py build`，图谱跟着变。

## 2. 条目字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `title` | ✅ | string ≤120 | 一句话说清这条是什么。**不要用「记录」「笔记」当标题**；它同时是 `[[双链]]` 的主标识 |
| `body` | ✅ | string ≤60000 | Markdown 正文。表格、`$LaTeX$`、`[[双链]]` 都可以 |
| `kind` | ✅ | enum | `note` / `question` / `method` / `link` / `image` / `dialog` / `mistake` |
| `column` | ⬜ | string | 专栏 slug，见 `columns.json`（`deepseek` / `math` / `logic` / `writing` / `english`）。不填则按 `tags[0]` 归类 |
| `aliases` | ⬜ | string[] | 别名，`[[别名]]` 也能指到这条。短的、常用的写这里 |
| `summary` | ⬜ | string ≤200 | 一句话结论（列表里显示这行，可用 `$...$`） |
| `tags` | ⬜ | string[] | 建议 2–4 个，第一个用学科（`数学`/`逻辑`/`写作`/`英语`） |
| `source` | ⬜ | object | `{agent, url, at, session}`，`at` 用 ISO8601；对话类把分享链接放 `url` |
| `refs` | ⬜ | object | `{questions:[], kps:[], links:[], images:[]}`，题号用 `"9"` 或 `"T1"`，考点用 id 或标题 |
| `id` | ⬜ | string | 不填则自动生成 `kb-YYYYMMDD-HHMMSS-<hash6>` |
| `hash` | ⬜ | string | 自动算 = sha1(title + "\n" + body)，用于去重 |

### kind 怎么选

| kind | 什么时候用 |
|---|---|
| `method` | 一类题的**通解**（判据、骨架、下手顺序） |
| `question` | 单道题的解析 / 变式 / 一题多解 |
| `mistake` | 错因复盘（我为什么错，下次怎么识别） |
| `link` | 外部资料、视频、文章 |
| `image` | 以图为主的材料（图放 `refs.images` 或公网 URL） |
| `dialog` | 与其他 Agent 的对话精华（保留提问原文 + 分享链接） |
| `note` | 以上都不是的杂项 |

## 3. 双链语法（v2 的核心）

正文里写：

| 写法 | 效果 |
|---|---|
| `[[条目标题]]` | 指到那条手记；标题不存在时变成红色「待建」，页面会给你一行可复制的 JSONL |
| `[[条目标题\|显示文字]]` | 同上，但显示 `显示文字` |
| `[[条目标题#小节]]` | `#` 之后忽略，只按 `#` 前解析（正文里没有锚点） |
| `[[判别式]]` | 指到考点。考点先按标题、短标签、前缀唯一匹配；歧义时取第一条并在 `check` 里报出来 |
| `[[第9题]]` `[[q9]]` `[[9]]` | 指到 2026 真题第 9 题 |
| `[[T9]]` | 指到母题 T9 |
| `[[kp:discriminant]]` | 指定考点 id，最不容易歧义 |

**代码块和行内代码里的 `[[…]]` 不算双链**（写例子安全）。

反向链接不用写，构建时自动算：B 的正文里出现 `[[A]]`，A 的详情页「被引用」里就会出现 B，并附上 B 那句话的上下文。

## 4. 最小示例

```json
{
  "kind": "method",
  "title": "和与积先解出两组，再用判别式砍掉一组",
  "summary": "$s+p=10,\\ sp=24$ 给出两组，只有一组在实数里成立",
  "column": "math",
  "aliases": ["和与积", "两组候选"],
  "tags": ["数学", "韦达定理", "通解"],
  "source": {"agent": "星际绘画", "url": "https://chat.example/abc", "at": "2026-11-16T10:00:00+08:00"},
  "refs": {"questions": ["9"], "kps": ["discriminant"]},
  "body": "## 通解\n解出 $\\{s,p\\}=\\{6,4\\}$ 之后……\n\n对比 [[判别式]] 和 [[韦达定理]]，原题见 [[第9题]]。"
}
```

## 5. 硬规则

1. **一条记录只讲一件事。** 一份对话里有 5 个结论 → 拆成 5 条，别塞成一条。
2. **标题必须是结论，不是话题。** ❌「关于假设题的讨论」 ✅「假设题先找结论里的新概念」。标题还是双链的主键，改名等于断链——想改就加 `aliases` 再写新条目。
3. **body 里不要写「如前所述」「上接」**——入库后条目是独立可读的。
4. **想连就写 `[[…]]`**，别只写「见考点库」。链接是这张图唯一的边。
5. **重复提交不会报错**，会返回已有 id（按 hash 去重）。所以放心重跑。
6. **不要放**：个人信息、手机号、微信截图里的头像、付费资料全文。

## 6. 校验失败会怎样

```
✗ 条目校验失败：「xxx」
  - kind 必须是 note/question/method/link/image/dialog/mistake 之一，当前 'misc'
```

错误会**指出字段名和当前值**，改完重跑即可，不会写入半条。

`python _data/kb.py check` 另外会报：断链（写了 `[[…]]` 但没这条）、歧义链接、重复标题、专栏 slug 拼错、孤立条目（没有任何链接进出）。
